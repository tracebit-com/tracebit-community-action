# AGENTS.md

This is a GitHub action that runs as a step in users' private and public repositories and depoys canary credentials in their workflow runs.
It should be fast and never fail their runs. It should plant the canaries in places which make sense for attackers who've compromised the workflow run
to find them, use the immediately or exfiltrate them and use them later. Using these credentials will create a Tracebit alert which is a
high-fidelity signal of the compromise.

- Do not edit files under `dist/`. The bundle is generated by `bun run build`.
- `dist/` is in `.gitignore` but tracked in git; use `git add -f dist/` after rebuilding.
- The action has three execution phases: `pre` (dist/pre.js), `main` (dist/index.js), and `post` (dist/post.js).
  - In sync mode: `pre` issues credentials, writes the AWS profile, and exports env vars. `main` only prints logs. `post` is a no-op.
  - In async mode: `pre` forks a detached child process to issue credentials in the background and writes a temp file path to `_SECURITY_CREDENTIALS_PATH`. The child writes the credentials file only after every deploy and confirmation has finished. `main` waits for that file, then exports and masks env vars for every family (AWS, SSH, npm, PyPI); the child never calls `core.*` because its output does not reach the runner. `post` reports error files written by the child, kills the child's pid, and removes the hand-off files. Canary files are left in place.
- `src/run-async.ts` is the child process entry point for async mode. It writes errors to `<credentialsPath>.error`.
- `src/validate.ts` validates every API response before anything is written. Keep two rules in tension:
  - Every value that is deployed must be checked against the grammar of where it lands (INI, `.npmrc`, `.netrc`, `~/.ssh`). Never write an API string to disk or the environment without a validator and a serializer from that file.
  - API changes must never break pinned action versions. Validation is per part: unknown top-level families, unknown strategies, extra fields, a malformed family, a malformed http instance or a bad candidate inside `any`/`all` are skipped with a `core.warning` and everything else still deploys. Only a body that is not JSON or not an object is an error. When adding a validator, drop and report the invalid part; do not throw out of `validateIssuedCredentials` or `validateConfig`.
- The action must never fail the customer's job. A missing `api-token` (fork pull requests) is a warning and a skip, not `setFailed`. Only missing `profile` / `profile-region` fail the main step.
- Files the action owns are replaced in place, never duplicated: the configured AWS profile section in `~/.aws/credentials` (the `~/.aws/config` section is only added when missing), and the SSH key named by `ssh-key-name`. Its `Host` block in `~/.ssh/config` is extended with an `IdentityFile` line if a block for that IP already exists. Existing npm and netrc entries for a host are left alone and not confirmed. Symlinks at any of these paths are refused.
- `src/external-types/deployment-strategy.ts` is auto-synced from `tracebit-com/tracebit`. Do not hand-edit; edit the upstream source and a sync PR will be opened against this repo.
- Tests are in `src/__tests__/`. Run with `bun run test`.
- Always run `bun run build` before running `bun run test`
